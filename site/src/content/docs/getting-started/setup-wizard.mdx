The **goiabada-setup** wizard is the easiest way to get Goiabada running. It generates configuration files with all credentials pre-configured.

## Download

Download the binary for your platform from the [releases page](https://github.com/leodip/goiabada/releases):

| Platform | Binary |
|----------|--------|
| Linux (x86_64) | [`goiabada-setup-linux-amd64`](https://github.com/leodip/goiabada/releases/latest/download/goiabada-setup-linux-amd64) |
| Linux (ARM64) | [`goiabada-setup-linux-arm64`](https://github.com/leodip/goiabada/releases/latest/download/goiabada-setup-linux-arm64) |
| macOS (Intel) | [`goiabada-setup-darwin-amd64`](https://github.com/leodip/goiabada/releases/latest/download/goiabada-setup-darwin-amd64) |
| macOS (Apple Silicon) | [`goiabada-setup-darwin-arm64`](https://github.com/leodip/goiabada/releases/latest/download/goiabada-setup-darwin-arm64) |
| Windows | [`goiabada-setup-windows-amd64.exe`](https://github.com/leodip/goiabada/releases/latest/download/goiabada-setup-windows-amd64.exe) |

The wizard will ask you a few questions:

1. **Deployment type**:
   - Local testing (HTTP) - for development
   - Production with reverse proxy - for Docker with Nginx/Cloudflare
   - Kubernetes cluster - generates Kubernetes manifests
   - Native binaries - generates environment file for running without Docker

2. **Database** - MySQL, PostgreSQL, SQL Server, or SQLite

3. **Domain names** - Your auth and admin console URLs (production/Kubernetes/native)

4. **Gateway traffic policy** (Kubernetes only) - The `externalTrafficPolicy` of Envoy Gateway's load balancer Service. `Cluster`, the default, works behind every load balancer, and Goiabada sees a node's address for every client; `Local`, with Envoy on every node as a DaemonSet, keeps the client's address at the cost of an Envoy pod per node. The answer decides the EnvoyProxy the wizard prints and the manifest's comments on which address the servers see (see [Kubernetes: Step 1](/production-deployment/kubernetes/#step-1-install-envoy-gateway)). `--gateway-traffic-policy=cluster` or `=local` answers without the prompt

5. **Network policy** (Kubernetes only) - Whether NetworkPolicies admit only Envoy's namespace to both servers, and the admin console to the auth server. No, the default, emits none, and any pod in the cluster can then reach both servers; yes needs a CNI that enforces NetworkPolicy, and refuses in-cluster callers of the auth server's Service until you admit their namespace (see [Kubernetes: who can reach Goiabada](/production-deployment/kubernetes/#who-can-reach-goiabada)). `--network-policy` answers yes without the prompt

6. **Reverse proxy** (native binaries only) - Whether a reverse proxy on the same machine, such as Nginx, forwards to Goiabada. Yes, the default, has both servers listen on `127.0.0.1` and trust its forwarded headers alone; no has them listen on every interface, trust no forwarded header, and wait for you to configure HTTPS. `--local-proxy=false` answers no without the prompt

7. **Admin credentials** - Email and password for the first admin user

8. **Database password** - A strong password (auto-generated if you press Enter)

## What gets generated

### For Docker deployments (options 1 and 2)

The wizard creates a `docker-compose.yml` file with:

- All session keys cryptographically generated
- OAuth client credentials pre-configured
- Database service configured
- Both auth server and admin console ready to start

Start with:

```bash
docker compose up -d
```

### For Kubernetes (option 3)

The wizard creates a `goiabada-k8s.yaml` file with:

- Namespace (labelled to warn about pods that break the restricted Pod Security Standard)
- Secret (credentials pre-generated and base64 encoded)
- One ConfigMap per server, holding only what that server reads
- Deployments (auth server and admin console), each with a PodDisruptionBudget
- Services
- Gateway and HTTPRoutes (TLS by cert-manager)
- NetworkPolicies, one per Deployment, if you asked for them

Deploy with:

```bash
kubectl apply -f goiabada-k8s.yaml
```

### For native binaries (option 4)

The wizard creates a `goiabada.env` file with:

- All environment variables for both auth server and admin console
- Session keys cryptographically generated
- OAuth client credentials pre-configured
- Database connection settings
- Listen hosts and proxy trust following your reverse proxy answer, under a comment saying whom each server trusts (see [native binaries: reverse proxy](/production-deployment/native-binaries/#reverse-proxy))

Use with:

```bash
set -a && . ./goiabada.env && set +a && ./goiabada-authserver
set -a && . ./goiabada.env && set +a && ./goiabada-adminconsole
```
