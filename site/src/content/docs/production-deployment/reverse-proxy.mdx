Use this setup if you're not using Cloudflare and want to manage SSL certificates yourself.

## Architecture

```
Internet → Nginx (HTTPS port 443) → {
    auth.example.com    → goiabada-authserver:9090 (HTTP)
    admin.example.com   → goiabada-adminconsole:9091 (HTTP)
}
```

Nginx handles HTTPS termination with Let's Encrypt certificates. Goiabada runs on HTTP internally.

## Prerequisites

- Two domain names (subdomains) for auth and admin console
- Nginx installed
- Docker and docker-compose installed

## Setup

### 1. Configure DNS records

At your DNS provider, add A records for both domains pointing to your server's IP address:

```
Type: A    Name: auth    Content: <your-server-ip>
Type: A    Name: admin   Content: <your-server-ip>
```

<Aside type="tip">
DNS propagation can take up to 48 hours, but usually completes within minutes. You can verify with `dig auth.example.com` or `nslookup auth.example.com`.
</Aside>

### 2. Start Goiabada containers

Use the [setup wizard](/getting-started/setup-wizard/) to generate your `docker-compose.yml`:

1. Select **"2. Production with reverse proxy"** when prompted
2. Enter your domain names (e.g., `https://auth.example.com` and `https://admin.example.com`)
3. The wizard automatically sets `TRUST_PROXY_HEADERS=true` with `TRUSTED_PROXIES` empty, trusting Nginx as the one proxy hop (see [client IP resolution](#client-ip-resolution-and-spoofing-protection)); and because your base URLs are `https://`, cookies get the `Secure` flag automatically

Then start the containers:

```bash
docker compose up -d
```

Verify containers are running:

```bash
# Check containers are running
docker ps | grep goiabada

# Test auth server health (should return: healthy)
curl http://localhost:9090/health && echo

# Test admin console health (should return: healthy)
curl http://localhost:9091/health && echo
```

### 3. Get SSL certificates

<Steps>
1. Install certbot (Ubuntu/Debian):
   ```bash
   sudo apt-get update
   sudo apt-get install certbot
   sudo mkdir -p /var/www/certbot
   ```

2. Create a temporary Nginx config for certificate acquisition:
   ```bash
   sudo nano /etc/nginx/sites-available/goiabada
   ```

3. Add temporary HTTP config:

   <Aside type="caution">
   Replace `auth.example.com` and `admin.example.com` with your actual domain names throughout this configuration.
   </Aside>

   ```nginx
   server {
       listen 80;
       server_name auth.example.com;

       location /.well-known/acme-challenge/ {
           root /var/www/certbot;
       }

       location / {
           proxy_pass http://127.0.0.1:9090;
       }
   }

   server {
       listen 80;
       server_name admin.example.com;

       location /.well-known/acme-challenge/ {
           root /var/www/certbot;
       }

       location / {
           proxy_pass http://127.0.0.1:9091;
       }
   }
   ```

4. Enable and reload:
   ```bash
   sudo ln -s /etc/nginx/sites-available/goiabada /etc/nginx/sites-enabled/
   sudo nginx -t && sudo nginx -s reload
   ```

5. Get certificates:
   ```bash
   sudo certbot certonly --webroot -w /var/www/certbot -d auth.example.com
   sudo certbot certonly --webroot -w /var/www/certbot -d admin.example.com
   ```
</Steps>

### 4. Configure Nginx

Create `/etc/nginx/sites-available/goiabada`:

```nginx
# Auth Server
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name auth.example.com;

    ssl_certificate /etc/letsencrypt/live/auth.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/auth.example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;

    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;

    location / {
        proxy_pass http://127.0.0.1:9090;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /.well-known/acme-challenge/ {
        root /var/www/certbot;
    }
}

# Admin Console
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name admin.example.com;

    ssl_certificate /etc/letsencrypt/live/admin.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/admin.example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;

    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;

    location / {
        proxy_pass http://127.0.0.1:9091;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /.well-known/acme-challenge/ {
        root /var/www/certbot;
    }
}

# HTTP to HTTPS redirect
server {
    listen 80;
    listen [::]:80;
    server_name auth.example.com admin.example.com;

    location /.well-known/acme-challenge/ {
        root /var/www/certbot;
    }

    location / {
        return 301 https://$host$request_uri;
    }
}
```

Enable and reload:

```bash
sudo ln -s /etc/nginx/sites-available/goiabada /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

### 5. Configure firewall

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
# Do NOT expose 9090 or 9091 to the internet
```

### 6. Set up certificate auto-renewal

Let's Encrypt certificates expire after 90 days. Set up auto-renewal:

```bash
# Test renewal
sudo certbot renew --dry-run

# Auto-renewal is typically configured automatically via cron or systemd timer
sudo systemctl status certbot.timer
```

## Access your deployment

- Auth server: `https://auth.example.com`
- Admin console: `https://admin.example.com`

## Client IP resolution and spoofing protection

Goiabada resolves the real client IP for rate limiting (auth server) and audit
logging. Behind a reverse proxy the direct connection comes from the proxy, so
Goiabada must read the forwarded headers to recover the original client IP.

- Setting `TRUST_PROXY_HEADERS=true` tells Goiabada to read `X-Forwarded-For` /
  `X-Real-IP` when resolving the client IP. With `TRUSTED_PROXIES` empty, it
  trusts a **single** proxy hop: the client is the rightmost `X-Forwarded-For`
  entry (or `X-Real-IP` when there is no `X-Forwarded-For`). The setup wizard
  writes both settings side by side, `TRUSTED_PROXIES` explicitly empty, under a
  comment saying why.
- One hop is sound behind any proxy that **sets or appends** `X-Forwarded-For`.
  The Nginx config above appends: `$proxy_add_x_forwarded_for` adds the address
  Nginx received the connection from to the right of whatever the client sent, so
  a value the client injects ends up on the left and is never read. Envoy and a
  Cloudflare Tunnel append the same way.
- What one hop does not survive is a caller that reaches Goiabada **without
  passing the proxy**: it connects directly and can send any `X-Forwarded-For` it
  likes, choosing the address it is rate limited and audited under. The wizard's
  Compose file publishes both ports on `127.0.0.1` alone, so only processes on
  this host can do that; keep it that way, and keep ports 9090 and 9091 closed in
  the firewall.

<Aside type="caution" title="A second proxy hop in front">
If a second proxy that appends `X-Forwarded-For` sits in front of the one that
connects to Goiabada (a load balancer in front of Nginx, for example), the
rightmost entry is that second proxy's address. Set `TRUSTED_PROXIES` to the
addresses of every hop you control, **including the one that connects to
Goiabada**: Goiabada reads the forwarded headers only from a connection whose
address is in the list, and walks `X-Forwarded-For` from the right past each
listed address to the first one that is not, the client.

For Cloudflare's proxy in front of Nginx, have Nginx resolve Cloudflare instead,
as the [Cloudflare + Nginx guide](/production-deployment/cloudflare-nginx/#client-ip-behind-cloudflare)
does, so Goiabada still sees one hop and needs no list.
</Aside>

```bash
# Example: Nginx on the internal network plus an upstream load balancer
GOIABADA_AUTHSERVER_TRUSTED_PROXIES=10.0.0.0/8,192.168.1.5
GOIABADA_ADMINCONSOLE_TRUSTED_PROXIES=10.0.0.0/8,192.168.1.5
```

<Aside type="note" title="Under Docker Compose the peer is not 127.0.0.1">
Nginx connects to `127.0.0.1:9090`, but the connection a Compose service sees
comes from the Compose network's gateway, an address such as `172.21.0.1`. A list
naming `127.0.0.1` therefore makes Goiabada ignore the forwarded headers and
resolve every request to the gateway, putting everyone in one rate-limit bucket.
With one proxy, leave the list empty. The [native binaries](/production-deployment/native-binaries/#reverse-proxy),
which Nginx reaches over loopback directly, are different: there the wizard
writes `TRUSTED_PROXIES=127.0.0.1`.
</Aside>

If you turn the rate limiter on while trusting one hop with no list, the auth
server logs a warning at every start saying so. It cannot tell a proxy that
appends from one that passes the header through untouched, nor see whether
anything reaches it around the proxy. Once you have checked both against your
setup, the warning is expected and can be left as it is.

<Aside type="tip">
If you enable a reverse proxy but forget `TRUST_PROXY_HEADERS=true`, every
request will appear to originate from the proxy's IP, so rate limits and audit
logs will attribute all traffic to a single address. This fails safe (it
throttles rather than opens a bypass), but it is a sign the flag is missing.
</Aside>
